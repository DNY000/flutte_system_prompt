# Memory Write Policy

Only durable knowledge should be written into memory.

## Write To `decisions.md` When

- an architecture choice is settled
- a package or framework direction is standardized
- a CI/CD rule becomes official

## Write To `patterns.md` When

- a solution is reusable
- the team wants a default pattern for similar features

## Write To `mistakes.md` When

- the same issue repeats
- the fix should become a future guardrail

## Do Not Write Memory For

- one-off debugging noise
- temporary experiments
- speculative ideas that are not approved

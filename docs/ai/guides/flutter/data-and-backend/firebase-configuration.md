# Firebase Configuration & DevOps Standards

## 1. The CLI Mandate

The AI MUST NOT recommend manually adding `google-services.json` or `GoogleService-Info.plist` files. 

*   **Primary Rule:** All Firebase projects MUST be initialized using the **FlutterFire CLI**.
*   **Initialization Code:**
    ```dart
    // In main.dart
    import 'package:firebase_core/firebase_core.dart';
    import 'firebase_options.dart'; // Generated by CLI

    void main() async {
      WidgetsFlutterBinding.ensureInitialized();
      await Firebase.initializeApp(
        options: DefaultFirebaseOptions.currentPlatform,
      );
    }
    ```

## 2. Environment Flavors Mapping

The AI MUST synchronize Firebase configuration with the application's environment flavors (`dev`, `staging`, `prod`).

*   **Command Pattern:** Proactively suggest the command: 
    `flutterfire configure --project=my-project-dev --out=lib/firebase_options_dev.dart`
*   **Dynamic Loading:**
    ```dart
    final options = switch (flavor) {
      Flavor.dev => dev.DefaultFirebaseOptions.currentPlatform,
      Flavor.prod => prod.DefaultFirebaseOptions.currentPlatform,
    };
    await Firebase.initializeApp(options: options);
    ```

## 3. Deployment Safety

*   **Consistency:** The AI must warn that running `flutterfire configure` updates the native build files. Always follow with a `flutter clean` if configuration issues arise.
*   **Secret Management:** Remind the user that `firebase_options.dart` is generally safe to source control as it contains public API keys, but the backend console must be locked with strict Security Rules.

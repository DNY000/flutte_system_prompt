# Output Contract Shells

Use these shells to standardize final answers.

When the runtime supports structured outputs, pair each shell with the matching contract entry from `docs/ai/core/contracts/structured-output-schemas.json`. The shell remains the human-readable render target.

## `design-spec-v1`

```text
Summary

User Goal

Screen Structure

Visual Direction

Visual Tokens

Interaction States

Accessibility

Flutter Composition

Risks
```

Design notes:

- `Screen Structure`: identify hierarchy, navigation context, and major layout regions
- `Visual Direction`: define tokens, density, emphasis, and style direction instead of vague adjectives
- `Visual Tokens`: capture exact colors, spacing, and type scales when the design needs handoff-ready values
- `Interaction States`: cover loading, empty, error, success, disabled, and offline when relevant
- `Accessibility`: include semantics, contrast, target size, focus order, and keyboard behavior where applicable
- `Flutter Composition`: end with concrete widget/layout mapping
